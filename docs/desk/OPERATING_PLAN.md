# Trading Desk 營運計畫(v2 主線)

> 2026-10-09 建立,2026-10-10 更新(全自動下單、逐筆核准停用、稽核結果)。取代舊系統「1-3 天選擇權方向預測」主線。舊程式碼保留,不刪。

## 1. 先講現實

**舊專案已經用數據證明的事**(2026-07 六個實驗,全部 walk-forward、扣成本、對照 baseline):
- 1-3 天選擇權擇時:沒有任何方法打贏「單純持股」。方向模型、新聞情緒、橫向動能,全部輸。
- 唯一可靠的報酬來源:股票本身的長期上漲(beta)+ 小幅的賣方波動率溢酬。
- 結論:**短天期 + 選擇權 = 每天付 theta 和價差的稅,邊際太薄。**

**新主線的回測**(股票、持有數週、順勢,2015-06 到 2026-10,規則事前固定、沒調參;2026-10-10 用最新資料重跑):

| | 年化 | 最大回撤 | Sharpe | 勝率 | 獲利因子 |
|---|---|---|---|---|---|
| 三策略合併 | 13.0% | -19.9% | 0.93 | 41% | 1.52 |
| SPY 買進持有 | 14.0% | -33.7% | 0.83 | - | - |
| 同一份清單等權 × 大盤濾網(稽核新增的對照組) | 14.9% | -21.8% | 1.17 | - | - |

- 原本記錄的 14.7% / Sharpe 1.03 是較早資料算的;資料更新到 2026-10-09 後是 13.0% / 0.93。
- **2026-10-10 稽核結論**(詳見 `docs/desk/EDGE_PLAN.md`):進場訊號打贏隨機進場,但整本書輸給「同清單、同曝險的等權持有」。主因是出場太緊(72% 的交易被停損出場,平均只賺 0.9%)。2024、2025 兩年各只賺約 3%。**目前還不能說這套系統有 edge**,紙上交易期的第一優先是修出場、建對照組。
- 回測有倖存者偏差(清單是今天的大型股);拿掉事後最強的 10 檔,年化掉到 7.9%。紙上交易才是誠實的測試。
- **勝率只有 39% 是正常的**。順勢靠「小賠多次、大賺少次」。目標是期望值(每筆平均報酬 × 次數),不是勝率。刻意拉高勝率(例如太早停利)通常會殺掉期望值。

**一個月紙上交易能證明什麼**:大約 20-60 筆交易,統計上不足以證明策略有 edge。這個月真正要驗證的是:
1. 流程跑得順(每天資料、訊號、成交、停損都正確)
2. 紙上結果和回測行為一致(沒有實作 bug)
3. 真實成交和模擬成交差多少(Alpaca 帳戶 vs 內部模擬 combined)
4. 你每天花的時間可持續

## 3. 系統架構:三層順勢確認

```
第一層 大盤     SPY vs 50/200 日線 + 市場寬度  -> 多頭順風 / 中性 / 空頭逆風 -> 決定總曝險上限(100% / 50% / 0%)
第二層 資金流向 12 個板塊 ETF 的 63 日相對強度    -> 領漲板塊(前 4 且贏 SPY 且站上 50 日線)
第三層 個股     多頭排列 + 相對強度 + 觸發條件    -> 進場訊號(附停損、論點、失效條件)
```

三個策略(都只做多,空頭時空手 = 順勢):
- **強勢突破** `breakout`:領漲板塊裡,放量創 55 日新高
- **多頭回檔** `pullback`:相對強勢股回測 20 日線後轉強
- **動能輪動** `rotation`:每月底持有動能最強的 5 檔

風控(機器強制執行,人不能關):每筆最多虧帳戶 0.75%、單檔最多 20%、最多 8 檔、同板塊最多 2 檔、移動停損(最高收盤 - 3 ATR)、跌破 50 日線出場。

帳戶(2026-10-09 起):
- **Alpaca 紙上帳戶**(帳戶 $10 萬,系統只把 $5 萬當自己的錢):三策略合併成一本書,**全自動下單**,每筆單都先過風控層(`desk/execution/risk.py`)。這就是實際在跑的帳戶。
- 內部模擬帳戶(`scripts/desk_daily.py`、`live.py`,各 25,000 USD 的 `breakout` / `pullback` / `rotation` / `combined`):保留作為對照,跟 Alpaca 帳戶比對「模擬成交 vs 真實成交」的差距。
- 原本「`desk` 帳戶每筆進場要人工核准」的設計已停用。人的判斷不再逐筆介入,改為透過規則變更、kill switch 與每日覆盤影響系統(見第 4 節)。

風控層額外的硬限制(機器強制,見 `execution/risk.py`):單筆訂單最多預算的 25%、加密貨幣總曝險最多 30%、下單價格偏離參考價超過 10%(加密 20%)直接擋;系統權益從高點回撤 -20% 新單減半、-35% 停止新進場;單一策略虧損超過預算 8% 停用該策略;`data/desk/HALT` 檔案或控制台開關 = kill switch。**以上都只擋新進場,出場和停損永遠放行。**

**待使用者決定(啟用 TQQQ 之前必須設定)**:風控層已有兩個 beta 調整後曝險上限,預設都是 `None`(停用,行為與以前完全相同):`Limits.max_beta_adj_exposure`(全部持倉按槓桿倍數加總,佔系統權益的比例)與 `Limits.max_growth_group_exposure`(美國大型成長股群組,成員與槓桿表見 `risk.py` 的 `GROWTH_GROUP`、`DEFAULT_LEVERAGE`)。數值由使用者依 `PHASE1_RESEARCH.md` 第 6 節的自助法結果決定,程式碼不內建。超限的買單會被縮小或擋下,理由寫在 `RiskDecision`;賣單不受影響。TQQQ 與 desk 月相關 0.71,是同一個風險因子的兩種槓桿,所以 TQQQ 以 3 倍計。

## 4. 人機分工

切分原則:**機器做「規則明確、需要紀律、需要記憶」的事;人做「需要脈絡、需要對規則本身負責」的事;AI 做「需要讀大量文字、需要整理」的事。**

| 工作 | 誰做 | 為什麼 |
|---|---|---|
| 抓資料、算指標、掃描 92 檔 | 機器 | 人做會漏、會累 |
| 停損、部位大小、曝險上限 | 機器,人不能關 | 人最容易在這裡破功(凹單、加碼攤平)。紀律交給機器 |
| 判斷大盤順風逆風 | 機器(規則) | 規則判斷穩定但慢。人覺得規則看錯時,不直接改單,而是開 kill switch 或提出規則變更,理由寫進日誌 |
| 下單、單筆部位大小 | 機器,全自動(2026-10-09 起) | 逐筆核准已停用。人對單筆的意見改用 kill switch 或「擋這一檔」的方式表達,只能減少風險 |
| 讀新聞與社群、確認訊號沒有被消息推翻 | 外部 agent(Muse,之後加 Grok)+ AI | 它們的輸入只能擋進場、不加碼、通知你,不能開倉或加碼(見 `MUSE_BRIDGE.md`) |
| 每日覆盤:機器摘要 | 機器 | 自動產生 |
| 每日覆盤:「我學到什麼」 | 人 | 這是累積經驗的唯一方式,機器替代不了 |
| 從日誌找規律、提出新策略假設 | AI + 人 | AI 能讀完一個月的日誌找重複模式;人判斷是否合理 |
| 驗證新策略 | 機器(回測 + 紙上影子帳戶) | 防止「感覺很對」的策略直接上線 |
| 改參數、加策略、決定上真錢 | 人 | 對系統本身負責的永遠是人 |

**機器的極限**(要知道,才不會過度相信):
- 只看價格與成交量,看不到「為什麼」。突發消息(併購、調查、政策)會讓技術訊號瞬間失效。
- 規則是從歷史歸納的。市場結構改變時(例如 2020 年 3 月),規則會慢半拍。
- 回測永遠比實盤好看(倖存者偏差、成交價理想化)。
- 不會「感覺不對勁」。

**人的極限**:
- 會在虧損時恐慌、獲利時貪心、連續贏之後過度自信。
- 會記住贏的、忘記輸的。
- 會在同一段歷史上反覆調參數,把雜訊當規律(過擬合)。

系統的設計就是讓兩邊互補:**人提供脈絡和判斷,機器提供紀律和記憶,所有人為決定都被記錄、之後被機器檢驗。**

## 5. 每日 / 每週 / 每月節奏

**自動排程**(launchd,美東,週一到週五;見 `src/stockmoney/desk/run.py`)
- 08:45 `premarket`:套用 Muse 旗標、過風控、送開盤市價單(先出場、再補停損、最後進場)
- 09:50 `postopen`:同步成交、掛券商端停損
  - 2026-10-21(帳戶擁有者決定):開盤單(OPG)若到期或被取消而未全數成交,`postopen` 對缺少的股數補送一次 DAY 市價買單;走同一套風控(上限、熔斷、kill switch、價格帶、當下的 Muse 旗標),被擋就不送並記錄原因;美東 10:30 後不補,剩餘股數作廢;已成交部分不重送,每筆計畫最多補一次(client id 結尾 `-rt`)
- 16:45 `postclose`:同步成交、對帳、上移停損、規劃隔天的單,寄日報
- 每 15 分鐘 `bridge`:收 Muse 的信;開機時 `recover`:補成交、補停損、清孤兒單

**每天盤後(你,約 10 分鐘)**
1. 讀手機上的日報:對帳是否乾淨、有沒有被擋的單、有沒有 Muse 警示
2. 「覆盤日誌」:寫一兩句「市場判斷」和「學到什麼」
3. 覺得不對勁時:開 kill switch(只停新進場),不要手動在券商下單

**每週末(約 30-45 分鐘)**
1. 看「績效」:Alpaca 帳戶 vs 內部模擬 combined vs SPY(兩者差距 = 實際成交的成本與執行問題)
2. 翻本週日誌,找重複出現的想法 -> 寫成可驗證的假設
3. 在「策略實驗室」回測假設;有理由、改善明顯才套用,而且寫理由

**每月底**
1. 檢討:每個策略的期望值、最大回撤、和回測是否一致
2. 被 Muse 或 kill switch 擋掉的訊號後來怎麼了?(擋得對 = 加分)
3. 決定下個月:哪個策略加碼、哪個停用、要不要加新策略

## 6. 怎麼正確地「提高勝率」

新策略或新規則一律走這條路,不能跳步:

```
日誌中的觀察 -> 寫成明確規則 -> 回測(要贏過 SPY 和現有策略,看信賴區間)-> 紙上影子帳戶跑至少 1 個月 -> 才進主帳戶
```

紀律:
- 一次只改一個東西,否則不知道是哪個改動有效
- 改動要有事前理由(「我認為 X 因為 Y」),不是「試試看哪個數字回測最好」
- 回測改善小於雜訊(信賴區間重疊)就不改
- 參數改動全部記錄在 `param_changes`,永遠可追溯

## 9. 掃描分類引擎(TypeSafe Jev)

`scripts/classify_scan.py --engine claude|jev|shadow`(預設 claude)。Jev(釘 `jev-1.13.0`)做高頻低複雜度判斷:相關性、是否值得升級為候選、各 ticker 的情緒;ticker 由程式碼找出,Jev 只判斷不生成。不確定、候選價值高或 Jev 出錯的項目升級給 Claude CLI。原始機率先寫入 `jev_judgments`(migration 041)再依門檻路由,門檻(`jev_classify.py` 常數)為暫定值。

驗證流程:
1. 影子期 5 個交易日:`--engine shadow`,套用 Claude 結果,Jev 只記錄(需 `TYPESAFE_API_KEY`,只放伺服器端,由使用者設定)。
2. 以 Sonnet 暫代標註建立驗證集,對照 `jev_judgments`,依資料校準門檻、檢查升級率與直接路由的準確度。
3. 通過後才切 `--engine jev`;防注入測試涵蓋不受信任文字只進 state。

目前只涵蓋 scan_classify,`news_synthesis` 尚未改。

## 10. 情報預篩層(TypeSafe Jev)

範圍:`bridge_messages` 裡的 GROK_DAILY(events / chains / attention)與 Muse 的 ALERT、RESEARCH_REPLY、IDEA、SOCIAL_DAILY 文字項目。CALLS 沒有自由文字,不預篩。程式:`src/stockmoney/desk/learn/prescreen.py`,表 `prescreen_judgments`,學習日報步驟 3d,`scripts/desk_prescreen.py`。

每個項目在一次 Jev 請求(釘 `jev-1.13.0`,不受信任文字只進 state)問三題:是否與交易相關(Noul)、是否為可具體追蹤的進展而非閒聊(Noul)、下行風險等級(Score,4 級)。程式碼路由,原始機率先寫入帳本,門檻(`prescreen.py` 常數)為暫定值:

| 路由 | 條件 |
|---|---|
| pass | 旁路(ALERT elevated/critical、有 risk_flags 的 RESEARCH_REPLY、GROK event severity critical/elevated),或 actionable >= 0.70,或風險分數 >= 2.0 且信心 >= 0.60 |
| archive | relevant < 0.30,或其餘低訊號 |
| hold | 介於兩者之間 |
| error | Jev 失敗,下次重跑 |

規則:
- 只標記,不刪除、不隱藏。chains / calls 的 5/20/60 日評分照常以全部資料計算,預篩只決定誰值得付費深度分析。
- 降低風險的訊號永不被過濾(旁路)。
- pass 的項目才進深度分析(Claude CLI,`--tools ""`,結果存 `deep_json`:傳導、受影響標的、風險備註、待查證項目)。輸出不接任何下單路徑,也不改任何參數。
- `DESK_PRESCREEN=off|shadow|on`,預設 off。shadow 只判斷與記錄,on 才做深度分析(每次最多 10 則,每項最多重試 3 次)。需 `TYPESAFE_API_KEY`(由使用者設定)。

驗證流程:
1. 影子期 5 個交易日:`DESK_PRESCREEN=shadow`,累積 `prescreen_judgments`。
2. 人工抽樣標註 pass / archive 各約 30 則(含已知結果的 chains),檢查被封存項目後來是否真的有影響(漏判率),依資料調整門檻。
3. 漏判率可接受後才切 `on`。

```bash
.venv/bin/python scripts/desk_prescreen.py items            # 列出待判斷項目(不呼叫 API)
.venv/bin/python scripts/desk_prescreen.py run --mode shadow
.venv/bin/python scripts/desk_prescreen.py report
.venv/bin/python -m pytest tests/desk/test_prescreen.py -q
```

## 11. 紙上積極期(2026-10-21 使用者指示:紙上要大膽,趕快找 pattern 和自己的交易方式)

**目的**:紙上交易沒有真錢風險,最貴的是時間。標準檔每月只有 20-60 筆交易,學不到東西。積極期用更大的下注和更多的位置換取樣本數,再用內部模擬帳戶(標準檔)當對照組,看「大膽」到底有沒有加分。

**實作**:`desk/profiles.py`,環境變數 `DESK_PROFILE=standard|paper_aggressive`(預設 standard)。

| | standard | paper_aggressive |
