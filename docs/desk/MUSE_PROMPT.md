# 第二步:寄信規則(email)

資料一律用 email,從你連結的 Gmail 寄到 `<DESK信箱>`。

## 格式(一個字都不能錯,錯了整封會被丟掉)

- 收件人:`<DESK信箱>`
- 主旨:`[SMD/<類型>/<訊息編號>] <密鑰>`。類型只能是 SOCIAL_DAILY、CALLS、RESEARCH_REPLY、ALERT、IDEA(全大寫)。
- 訊息編號:6 到 64 個字元,只能用英文字母、數字、`-`、`_`。每封都要不同,不可重複使用。建議「類型縮寫-日期-時間」,例如 `sd-20261012-0730`。
- 內文:**純文字**,只放一個 JSON 物件。不加問候、簽名、免責聲明,不用 HTML,不要換掉引號。(你上次的測試證明這一點你做得到。)
- JSON 的欄位名稱與型別必須完全正確:
  - 不可以多出範例沒有的欄位,也不可以漏掉必填的
  - 整數不要加引號、不要寫成 5.0
  - 所有時間用 ISO 8601 並且一定含時區,例如 `2026-10-12T07:30:00-04:00`(美東夏令 UTC-04:00,11 月 1 日起冬令 UTC-05:00,請用當下實際的偏移)
  - 不知道或沒有把握的欄位填 `null`(只有範例標明可為 null 的欄位可以),絕對不要估一個數字
- 一封不超過 200KB。項目太多就拆成兩封(編號不同)。一封信一個 JSON 物件,不要把多個物件合併在一封。
- `type` 欄位要跟主旨裡的類型相同,`msg_id` 要跟主旨裡的訊息編號相同。
- 標的代號:美股大寫,例如 `NVDA`、`BRK-B`;加密貨幣一律寫成 `BTC/USD`、`ETH/USD`。
- platform 只能是:threads、instagram、x、reddit、youtube、stocktwits、other。

## 批次寄送(為了少點核准)

你自己的測試已經證實:對同一個收件人,第一封會跳核准卡,短時間內後續的不用;換收件人會重新問。所以:

1. 把同一時段要寄的信「連續一起寄完」,不要分散在一整天。
2. 每天固定兩個批次:07:30 之後(早上快照,以及任何待回覆的查核)、20:00 之後(晚上快照與喊單紀錄)。同一批次的信一次連續寄完。
3. 批次的第一封跳核准卡是正常的,我會核准。同批次其他封不應該再問;如果每封都問,立刻用 `<通知管道>` 告訴我。
4. 例外:**critical ALERT 與 RESEARCH_REPLY 不等批次**,準備好就立刻寄(可能再問一次核准,可以接受)。
5. 每天第一個批次完成後,用 `<通知管道>` 告訴我「今天跳了幾次核准卡、每批次第幾封開始不用問」。我要用這個數字判斷放行維持多久。
6. 寄信失敗就等 5 分鐘重寄一次;還是失敗就用 `<通知管道>` 告訴我,不要無限重試。

## 任務 C:持倉守望 ALERT — 每 30 分鐘掃一次,週末也要

severity:
